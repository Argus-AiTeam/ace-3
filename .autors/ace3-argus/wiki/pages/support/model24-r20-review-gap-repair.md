# Model24 r20 review-gap repair boundary

The r20 preparation package preserves the complete r19 candidate and its
independent L2 REJECT review as byte-authenticated, recursively read-only,
non-reusable ancestry. The r19 review hash and both decisive findings are
bound by the r20 package seal. The inherited r18 crash classification remains
unchanged: layers 0 through 8 are authenticated partial evidence, layer 9 is
incomplete, and no execution output is reusable.

The controller-entry preparation probe is a standalone standard-library
fixture. It exclusively creates temporary fixture paths, writes and
authenticates three synthetic artifacts, and proves directory creation occurs
before fixture entry. It does not import or invoke the lifecycle, production
controller, Model24 model, RTL simulator, or canonical payload. Fixture calls
and artifact authentications have explicit counters; all real controller,
Model24, RTL simulator, lifecycle, and binary invocation counters remain zero.

Review validation requires exactly one result for each of the 13 named reboot
crash cases and requires every result to be `PASS`. Missing, extra, duplicate,
substituted, malformed, or non-PASS entries fail closed. The inherited 59
negative cases and six positive fixtures remain required; omission and
substitution review mutations extend the negative suite to 61 cases.

Preparation compiles layers 0 and 23 from recursively read-only source into a
fresh external post-seal build root without executing either binary. The fresh
review, authority, canonical output, receipt, logs, and terminal namespaces
remain absent.

## V11 no-execution directive preflight

The V11 preflight is a readiness artifact, not execution authority. It binds
the accepted r20 package manifest, package seal, independent ACCEPT review,
unconsumed one-shot authority, V10 adoption receipt, and adopted project
authority by exact byte count and SHA256. It preserves the launch identity and
one-shot controls while explicitly leaving authority consumption, durable
submission, workload execution, and output or terminal publication
unauthorized.

The durable preflight is
`build/model24_selected_token_position3_continuations/r20-v11-directive-preflight/preflight.json`
with SHA256
`27ef9d1251a9c3254b4aa9f76a5f0c5c32dda05aa2e7f7eb23de53ffa1927eea`.
Its adjacent validation log records `authority_consumed=false`,
`execution_authorized=false`, all workload counters zero, and every declared
execution, output, and terminal namespace absent. The preflight snapshots the
exact V10 Manager mission bytes with SHA256
`4c84b1848a3074928a389653477bc2e5750a76ded3b429506b612875c44cb5e5`,
so later `latest.json` rotation cannot change that provenance.

A later execution authorization must provide new immutable Manager-owned V11
directive bytes and bind their digest, this preflight's exact digest, the
adopted project-authority preimage, the adoption receipt, all accepted r20
evidence, the exact launch tuple, and the one-shot no-replay controls. Those
future fields are enumerated in the preflight, but no such authorization is
present in this boundary.

## V11 runtime-pass admission candidate

The runtime-pass admission candidate is a zero-workload gate between the V11
directive and any project-authority authorization. It snapshots and
byte-authenticates the canonical Manager V11 directive, the accepted
no-execution preflight, the adopted project-authority preimage, the V10
adoption receipt, and the independently accepted receipt-chain task. The
receipt-chain binding names reviewed source commit
`72ce3acf6ae88806c17a39c9c68a1a32928cfcbf` and its exact tree.

The candidate also binds the accepted r20 manifest, seal, independent review,
unconsumed authority, exact cwd and argv, execution cardinality one, and false
retry, replay, resume, and watcher controls. Validation rejects stale
preflight bytes, receipt-chain drift, missing or substituted directive bytes,
consumed authority, replay markers, and launch-tuple drift.

The immutable candidate retains status `AWAITING_INDEPENDENT_REVIEW`; it does
not accept itself. Independent review subsequently accepted its exact
`e8825602d620156adde47f01a95c07aa1154b0027e7b22f6084dea214ff71735`
bytes. The independent PASS review is
`build/runtime-pass-admission/evidence/review.json`, SHA256
`f95c848f48c8177cbdec8de7d5cad1d0903c526ed28cb1863e2159194ad9d5f3`.

## Future selected-token terminal receipt provenance

The host terminal adapter accepts only a future selected-token record that
binds nonce `18357ce16f61ddae`, the matching r20 task ID, the accepted package
manifest, package seal, independent review, accepted one-shot authority, and
the V11 no-execution preflight by their fixed digests. It separately requires
an exact caller-authenticated future V11 execution-directive artifact record;
this field does not imply that such a directive currently exists.

The adapter rejects replay, ordinal or token-history discontinuity, terminal
parent drift, and unauthorized or consumed receipt-use authority. It performs
in-memory validation and receipt canonicalization only. It does not read or
consume project execution authority, publish terminal evidence, submit work,
or invoke the r20 package.
